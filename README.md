# VergeOS Docs

Source content for the **VergeOS Docs** site, published with GitBook at
<https://docs.verge.io>.

This is a **GitBook Git Sync monorepo**: each top-level directory is the Project
directory for one GitBook *space*, and GitBook renders the Markdown on sync. There is
no app to build, lint, or test — editing the Markdown and pushing to `main` updates the
site.

## Spaces

Each directory below git-syncs to one space and maps to a navigation section on the site.

| Directory         | Site section                  | Space                         |
| ----------------- | ----------------------------- | ----------------------------- |
| `home/`           | Overview (site root)          | Home                          |
| `deploy/`         | Plan and deploy               | Plan and deploy               |
| `run/`            | Run the platform              | Run the platform              |
| `automate/`       | Automate, protect, and extend | Automate, protect, and extend |
| `learn/`          | Learn the platform            | Training                      |
| `knowledge-base/` | Knowledge base                | Knowledge base                |
| `release-notes/`  | Release notes                 | Release notes                 |

The site also has an **API Reference** space that is *not* in this repo — it has no
source equivalent and is edited directly in GitBook.

## How a space is laid out

Every space directory follows GitBook's conventions:

- **`.gitbook.yaml`** — sync config: `root: ./`, `structure.readme: README.md`,
  `structure.summary: SUMMARY.md`.
- **`README.md`** — the space's root page. Frontmatter uses `description` + `icon`.
- **`SUMMARY.md`** — the table of contents and the **source of truth for sidebar order
  and titles**. `## Group` headers become sidebar groups; `* [Title](path.md)` bullets
  are pages. The link text — not the page H1 — is what shows in the sidebar.
- **Content `.md` files** — organized in subfolders (e.g. `run/product-guide/storage/`).
- **`assets/`** — images for that space only (GitBook does not share assets across
  spaces); screenshots live under `assets/screenshots/`.

> **When you add or move a page, update that space's `SUMMARY.md`** — otherwise it won't
> appear in the sidebar.

### Cross-space links

A link to a page in another space must use that space's GitBook ID:
`https://app.gitbook.com/s/<spaceId>/<dest-path-without-.md>`. Links within the same
space stay relative (`../storage/overview.md`).

## Editing workflow

1. Edit Markdown (and `SUMMARY.md` if you added/moved/renamed a page).
2. Commit and push to `main`.
3. GitBook syncs automatically and the change goes live.

Git Sync makes this repo the source of truth: a push overwrites the corresponding space
content in GitBook.

## Redirects

`redirects.csv` maps every URL from the previous docs site to its new location, for
GitBook's **Settings → Redirects → Add redirects** bulk importer (max 500 rows). It was
generated by joining the old site's `sitemap.xml` to each GitBook page's published path
via the migration mapping. `redirects-test.csv` is a two-row sample for verifying the
import format before loading the full set.

## Migration tooling

`migration/` holds the one-time scripts that ported the content from the old MkDocs
source site. See [`migration/README.md`](migration/README.md). You don't need these for
normal edits — only to regenerate a space from source.
